# CopeTech-Edgar — Architecture & Capability Audit

**Date:** 2026-07-29 · **Branch:** `codex/financial-series` · **Scope:** whole repository
**Baseline at start:** 115 tests passing, `tests/test_app.py` failing to collect (29 tests unrunnable)
**State at end:** 215 tests passing, 0 collection errors

Every Critical and High finding below was reproduced against real SEC documents or the
official SEC XML technical specifications before being written down. Where a fix was
applied, the "after" behavior was re-verified against the same source document.

---

## 1. Executive assessment

### What CopeTech-Edgar is today

A working, async, single-facade SEC EDGAR client (~4.6k LOC of library code) built around
`SECDataFetcher`, extracted from an earlier project ("Sentinel"). It reliably does five
things: resolve tickers to CIKs, pull submissions and Company Facts, list filings by form,
parse ownership/144/13F XML, and derive an insider-activity payload shaped for a UI and an
LLM. It also ships an optional FastAPI demo service and an AWS deployment.

It is **not** currently a general SEC-data library. It is a Form 4 insider-signal product
with four additional datasets bolted on, each written to a different internal convention.

### Is the foundation sound?

**The skeleton is sound; the flesh is not.** Three structural decisions were right and
should be preserved:

1. **Facade + injected processors.** `SECDataFetcher` composes `Form4Processor`,
   `Form144Processor`, `ThirteenFProcessor`, `FinancialSeriesService`… each receiving its
   dependencies as callables. This is genuinely testable and is why 215 unit tests run in
   2 seconds with zero network access.
2. **The immutable raw filing store** (`cache_manager.RAW_FILINGS_SUBDIR` +
   `document_handler.RawFilingResolver`). Keying downloads by accession number, treating
   filed documents as immutable, and de-duplicating in-flight requests is exactly right and
   is the single best idea in the repository. Parser fixes cost zero SEC traffic.
3. **The new `financial_series` module** (Codex's work) is a different and much higher
   standard than everything around it: a metric registry, per-fact provenance, quality
   flags, point-in-time `as_of` filtering, an append-only fact store keyed by accession.
   **This is the model the rest of the library should converge on**, not an outlier.

What is not sound is the layer where data becomes numbers. Five defects were returning
materially incorrect values, and the reason they survived is structural: **the XML parsers
and the HTTP client had no test coverage at all**, and the library has no error model, so
every failure mode degrades to `None`/`[]`/`{}`.

### The largest risks to expansion

| # | Risk | Why it blocks growth |
|---|---|---|
| 1 | **No error model.** Zero library-defined exception types; `make_request` returns `None` for 404, timeout, throttling, malformed JSON, and oversized body alike. | Every new dataset inherits "silently returns empty". The 13F zero-portfolio artifact in `scripts/_smoke_artifacts/` is this failure mode captured on disk. |
| 2 | **No shared SEC resource model.** CIK is normalized five different ways inline; there is no `Filing`, `Issuer`, `Accession`, or `Provenance` type. Everything is `Dict[str, Any]`. | Each added dataset re-invents identity and provenance, and cross-dataset joins are unsafe. |
| 3 | **Submissions history is capped.** Only `filings.recent` is ever read; `filings.files[]` is never followed. | Any question older than ~1 year / 1,000 filings is unanswerable. This directly limits the long-history retrieval Codex needs. |
| 4 | **Ticker-keyed caching.** Cache keys are tickers, not CIKs, and the ticker→CIK map is never refreshed once written. | Ticker reuse and ticker changes silently return the wrong company's data. |
| 5 | **Three copies of the metric concept chain** (now two, after this audit deleted the dead third). | Financial semantics drift between call sites. |

### The most important next move

**Give the library an error model and a resource model — in that order — then follow
`filings.files[]`.**

Not a rewrite. Concretely: add `copetech_sec/exceptions.py` and
`copetech_sec/identifiers.py`, make the HTTP layer raise instead of returning `None`, and
key caching on CIK. That is roughly 400 lines of new code and it converts every future
dataset from "another special case" into "another resource module". Everything else on the
roadmap is cheaper afterwards.

### Traced execution paths

**(1) Fetch and parse a Form 4**
```
SECDataFetcher.get_insider_signal_payload(ticker)
└─ Form4Processor.get_insider_signal_payload
   ├─ fetch_filings_metadata → SECDataFetcher.fetch_insider_filings
   │  └─ get_filings_by_form(["4","4/A"])
   │     ├─ cache_manager.load_data('forms', form_type="4,4/A", days_back=N)   [day-stamped]
   │     └─ get_company_submissions → cache_manager.load_data('submissions')
   │        └─ http_client.make_request(SUBMISSIONS_ENDPOINT)     ← reads filings.recent ONLY
   ├─ _payload_fingerprint(accessions, window, version)  → cache hit short-circuits
   ├─ per accession: RawFilingResolver.get_xml
   │  ├─ cache_manager.load_raw_filing(accession)        [immutable; download-once]
   │  └─ document_handler.download_form_xml
   │     ├─ _get_cik_for_filing (explicit cik → ticker lookup → accession prefix)
   │     ├─ get_filing_documents_list → make_archive_request(index.json)
   │     └─ download_form_document → make_archive_request(document)
   ├─ Form4Processor.parse_form4_xml         → List[Dict] rows
   ├─ _normalize_signal_event                → event dicts
   ├─ _dedupe_and_apply_amendments → _build_daily_aggregates → detect_cluster_buys → _build_llm_digest
   └─ cache_manager.save_data('insider_signals', …)      [fingerprint-validated, fixed filename]
```
Note the CIK is resolved **three times** per document (`download_form_xml`,
`get_filing_documents_list`, `download_form_document` each call `_get_cik_for_filing`).

**(2) Ticker → CIK**
```
get_cik_for_ticker(ticker)
├─ cache_manager.load_cik → reads mappings/ticker_cik_map.json   ← NO freshness check
└─ on miss only: _fetch_and_cache_cik_map()
   └─ make_request("https://www.sec.gov/files/company_tickers.json", headers with Host: www.sec.gov)
      └─ {ticker.upper(): cik.zfill(10)}   ← last-writer-wins across share classes
```

**(3) Submissions / filing history** — `get_company_submissions` → day-stamped cache →
`make_request`. `get_filings_by_form` then iterates the `recent` columnar arrays,
zip-truncating on `min(len(form), len(filingDate), len(accessionNumber), len(reportDate))`.
`filings.files[]` is never consulted.

**(4) Company Facts** — `get_company_facts` → `cache_manager.load_data('facts')`
(timestamped to the second, fresh only if today) → `make_request`. Consumed by two
independent normalizers: `FinancialDataProcessor` (legacy) and `FinancialSeriesService`
(new).

**(5) Filing → domain model** — there is no domain model. Every parser returns
`List[Dict[str, Any]]` with parser-specific keys.

**(6) Caching / persistence** — four independent stores: filesystem JSON
(`SecCacheManager`), immutable raw filings (same class, different rules), `data/sentinel.db`
(`SqlCacheManager`), `financial_series.sqlite3` (`FinancialSeriesStore`). No shared
interface, no shared invalidation.

**(7) Error propagation** — see §7. Summary: it doesn't. HTTP failures become `None`, which
processors convert to `[]`/`{}`.

## 4. Architecture findings by severity

### CRITICAL

---
#### C-1 · Rate limiter provides no protection under concurrency (SEC fair-access violation)
**Location:** `http_client.py:156-163` (original) — `make_request` / `make_archive_request`
**Observed:** check-then-sleep against a shared `last_request_time` with no lock. Concurrent
callers all read the same stale timestamp, compute the same sleep, sleep *in parallel*, and
dispatch together.
**Evidence (measured):** 50 concurrent `make_request` calls at `rate_limit_sleep=0.1`
(10 req/s) dispatched **all 50 within 101 ms** — peak 50 requests in a 1-second window,
≈492 req/s effective.
**Why it matters:** SEC states *"no more than 10 requests per second, regardless of the
number of machines used to submit requests"* and reserves the right to block IPs. Reachable
from public API: `fetch_multiple_tickers` and `download_all_form_documents` both use
`asyncio.gather`, and `app.py` shares one `SECDataFetcher` across concurrent HTTP requests.
**Fix applied:** `_acquire_request_slot()` — a monotonic reservation cursor advanced under
`asyncio.Lock`; the lock covers only the arithmetic, the wait happens outside it. Both the
data and archive paths draw on the one budget (correct: the SEC limit is per *user*).
**Migration risk:** none for correctness; throughput of concurrent bursts now correctly
throttles to the configured rate (that is the point).
**Tests:** `tests/test_http_client.py::ConcurrentRateLimitTests` (3 tests: spacing, no-burst
window, shared archive/data budget).

#### C-2 · All Form 13F values inflated 1000×
**Location:** `thirteenf_processor.py:216` (original) — `"value": value_thousands * 1000`
**Observed:** the reported `<value>` column is multiplied by 1,000.
**Evidence (live SEC):** Berkshire Hathaway 13F-HR `0001193125-26-226661`, first row:
`<value>498992850</value>` for `<sshPrnamt>12719675</sshPrnamt>` Ally Financial shares —
$499 M for 12.7 M shares ≈ $39/share, i.e. **already whole dollars**. Portfolio total was
reported as **$263,095,703,570,000 ($263 trillion)** against an actual ≈$263 billion.
The 13F schema (`eis_13FDocument.xsd`, spec v1.9) types the element
`INTEGER_NONNEGATIVE_16_1` — a 16-digit integer, which a thousands-scaled column would never
need.
**Root cause:** Form 13F as amended effective 2023-01-03 (SEC Release 34-96492) reports
value in whole dollars; it was in thousands before that.
**Fix applied:** `value` passes through unscaled; `value_usd` added as an explicit alias;
`value_thousands` removed.
**Migration risk:** **breaking for any consumer reading `value_thousands`** and any stored
values. CopeNet does not read it (checked). Pre-2023 filings, if ever parsed, are now
under-reported 1000× — a separate, documented gap (see D-2).
**Tests:** `test_thirteenf_processor.py::test_reported_value_is_not_rescaled` (includes an
implied-price plausibility assertion).

---
#### C-3 · 13F quarter-over-quarter diff silently discards ~68% of holdings
**Location:** `thirteenf_processor.py:264-265` (original)
`{_holding_key(row): row for row in holdings}`
**Observed:** a filer may report one security across many rows (one per `otherManager`
attribution — `otherManager` is `minOccurs="0"` in the schema). The dict comprehension keeps
**only the last row per (cusip, put/call, class)**.
**Evidence (live SEC):** Berkshire's filing has **90 rows covering 29 securities** →
**61 rows (68%) dropped with no warning**. `totals` was computed over the full row list
while the change buckets came from the collapsed dict, so totals never reconciled with the
buckets.
**Fix applied:** `_aggregate_by_security()` rolls rows up to one economic position per
security, summing `value` and `shares` and recording `row_count`.
**Verified after fix:** 90 rows → 29 positions, total $263.1 B, top holdings Apple
$57.8 B / 227.9 M sh, Amex $45.9 B, Coca-Cola $30.4 B / **exactly 400,000,000 shares** —
matching Berkshire's long-known position.
**Tests:** `test_thirteenf_processor.py::MultiRowPositionTests` (4 tests incl. a
bucket↔totals reconciliation test).

#### C-4 · Financial summary returns duplicated and mislabeled periods
**Location:** `financial_processor.py:90-129` (`_format_period`), `:269-334`
(`_deduplicate_entries`) — **Codex's territory; documented, not fixed.**
**Observed:** `_format_period` labels a fact from `frame` when present and from `fp`+`fy`
otherwise. These are **different calendars**: `frame` is calendar-aligned (`CY2025Q1`),
while `fy`/`fp` are the fiscal year/period **of the filing that reported the fact**, not of
the fact itself. The same economic fact therefore gets two different labels, and
`_deduplicate_entries` groups on `(period, date)` — so both survive.
**Evidence (AAPL fixture `data/edgar/facts/AAPL_facts_20260510_191103.json`):** for period
end `2025-03-29` the raw facts are
```
start 2024-12-29 end 2025-03-29 val 95359000000 fy 2025 fp Q2 frame None        → labeled "Q2 2025"
start 2024-12-29 end 2025-03-29 val 95359000000 fy 2026 fp Q2 frame CY2025Q1    → labeled "Q1 2025"
```
The extracted quarterly revenue series has **53 rows with 22 duplicated period-end dates**
(one triplicated). The committed artifact `scripts/_smoke_artifacts/trend_AAPL.json` shows
this in production output, including two rows both dated `2025-03-29` and a resulting
`qoq_pct: 0.0` (a row compared against its own duplicate) — because `compute_trend`
computes QoQ/YoY by **positional offset** (`index+1`, `index+4`), which is invalid once the
series contains duplicates or gaps.
**Why it matters:** revenue charts and every QoQ/YoY figure derived from
`get_financial_summary` / `get_financial_trend` are wrong. `SqlCacheManager` then persists
them under `UNIQUE(ticker, metric, period_end_date)`, collapsing duplicates
non-deterministically.
**Recommended fix (Codex):** this is precisely what `financial_series.py` already solves
correctly — it keys on `(period_start, period_end, unit)` and preserves fiscal identity
separately from calendar frames. **Retire `financial_processor`'s period logic in favor of
the `financial_series` resolver** rather than repairing it. Interim: label from
`(start, end)` only, never from `fp`+`fy`; dedupe on `(period_start, period_end, unit)`;
prefer latest `filed`, not smallest value.
**Required test:** an AAPL-shaped fixture asserting one row per distinct `(start, end)` and
no duplicate `periodEnd`.

#### C-5 · Form 4 direction derived from a code table, contradicting the filing
**Location:** `form4_processor.py:73-74`, `:193-194`, `:243-244` (original)
**Observed:** `is_acquisition = tx_code in ACQUISITION_CODES`. The filing's own
`transactionAcquiredDisposedCode` was parsed into `acq_disp_code` and then **never used**.
Codes `M`, `C`, `G`, `J`, `W`, `K`, `Z`, `I` are direction-neutral — direction is a
per-transaction fact.
**Evidence (live SEC):** Apple Form 4 `0001140361-26-025622` (an RSU settlement) contains
three rows. The derivative leg is `transactionCode=M` with
`transactionAcquiredDisposedCode=D`, yet the parser reported `is_acquisition=True`. Both
legs of the same settlement were counted as acquisitions: **30,104 shares acquired reported
as 60,208**. `analyze_insider_transactions` computes `total_buy_value`, `total_sell_value`
and `net_value` from these booleans.
Also: `TRANSACTION_CODE_MAP['W']` was labeled *"Warrant Exercise"*; per SEC, `W` is
*acquisition or disposition by will or the laws of descent and distribution*. Seven codes
(`V`, `E`, `H`, `O`, `K`, `L`) were missing entirely.
**Fix applied:** `_resolve_direction()` reads `transactionAcquiredDisposedCode` first,
falling back to a narrow, honestly-named hint set (`ACQUISITION_CODE_HINTS` /
`DISPOSITION_CODE_HINTS`) only when the filing omits it. Full 21-code table with SEC wording.
Old names retained as aliases.
**Verified after fix:** all three Apple rows agree with the filing; across SEC's six
official sample ownership documents, **zero rows** carry both flags and 100% match the A/D
code.
**Tests:** `tests/test_form4_parser.py::TransactionDirectionTests` (6 tests + 23 subtests).

#### C-6 · Form 4 parser reads only the first reporting owner; Forms 3/5 return nothing
**Location:** `form4_processor.py:148-152`, `:175`, `:222` (original)
**Observed:** `findtext('.//reportingOwner/reportingOwnerId/rptOwnerCik')` returns the
**first** match. The Ownership XML Technical Specification (v5.5) declares
`<xs:element name="reportingOwner" … maxOccurs="10"/>`. Separately, only `*Transaction`
elements were queried — `nonDerivativeHolding` / `derivativeHolding` were dropped, and the
**Form 3 schema contains no transaction elements at all**.
**Evidence (SEC's own reference documents, Ownership XML Tech Spec v5.5):**
| sample | table rows in XML | parsed before | parsed after |
|---|---|---|---|
| `doc3.xml` (Form 3, 2 owners) | 2 | **0** | 2 |
| `doc4.xml` (Form 4, 3 owners) | 6 | 3 (of 6; owners 2–3 lost) | 6 |
| `doc5.xml` (Form 5, 3 owners) | 6 | 4 | 6 |
**Fix applied:** `_parse_reporting_owners()` returns every owner with its own relationship
flags, exposed on each row as `reporting_owners` / `owner_count` / `is_joint_filing`.
All four table row types are parsed, tagged `is_holding`.
**Design note — a flaw in the first version of this fix, caught by testing against SEC's
samples:** emitting one row per (owner × table row) turned `doc4.xml`'s 6 real transactions
into 18 records, inflating shares and value 3×. The schema carries **no per-row owner
attribution**, so the corrected implementation emits exactly one record per table row,
keeps `owner_*` as the primary owner for backward compatibility, and exposes the full owner
list alongside. Parsed row count now equals XML table row count exactly for all six samples.
**Migration risk:** row counts increase for filings containing holdings. Holdings are
excluded from `get_insider_signal_payload`'s event stream (they are position statements,
not events) so the compatibility-sensitive payload's counts are unchanged.
**Tests:** `MultipleReportingOwnerTests` (5), `HoldingRowTests` (4).

#### C-7 · Numeric parsing silently returned 0.0 for valid values
**Location:** `form4_processor.py:188-190`, `:237-240` (original)
`float(s) if s and s.replace('.','',1).isdigit() else 0.0`
**Observed:** any value that is not a bare unsigned decimal became **zero**: whitespace-
padded values (`<value>\n  1000\n</value>`, produced by some filer agents), negatives,
thousands separators, scientific notation. A missing `transactionPricePerShare` (normal for
gifts and awards) defaulted to `'0'`, so `value = shares × 0 = 0.0` — a $10 M grant recorded
as $0.
**Evidence (executed):** `1000` with surrounding whitespace → `shares=0.0, value=0.0`;
`-500` → `0.0`; `1,000` → `0.0`.
**Fix applied:** `_parse_decimal()` strips, removes separators, and returns `None` on
failure so a parse error is distinguishable from a real zero. `value` is `None` unless a
genuine price was reported.
**Migration risk:** consumers must handle `None` where they previously saw `0.0`. All
in-repo consumers use `.get(...) or 0.0` / `pd.to_numeric(errors='coerce')` and were verified.
**Tests:** `NumericParsingTests` (6).

### HIGH

**H-1 · No error model.** Zero library-defined exception types. `make_request` returns
`None` for 404, timeout, connection failure, malformed JSON, oversized body, and exhausted
retries alike, and on JSON-decode failure returns *raw text* — so callers doing
`isinstance(response, dict)` treat an SEC error page as "no data". Processors convert `None`
to `[]`/`{}`. **A caller cannot distinguish "this issuer has no Form 4s" from "SEC throttled
us".** The committed `scripts/_smoke_artifacts/13f_changes_0001067983.json` is this failure
captured on disk: Berkshire Hathaway with `prior_value: 0, current_value: 0` and every
bucket empty. *Recommended:* `exceptions.py` with `EdgarError` → `IssuerNotFound`,
`FilingNotFound`, `ThrottledError`, `TransportError`, `MalformedResponseError`,
`ParseError`, `UnsupportedFilingError`, `AmbiguousConceptError`. Raise in the transport
layer; keep `None` only where absence is a legitimate answer.

**H-2 · Ticker-keyed cache; ticker→CIK map never refreshed.** `cache_manager.load_cik`
reads `ticker_cik_map.json` with no freshness check, and `_fetch_and_cache_cik_map` runs
only on a cache *miss* — so once written the map is permanent. New listings never resolve;
renamed tickers resolve to the old company. All ticker-keyed cache files inherit the
problem. *Recommended:* key caches on CIK, TTL the map (weekly), keep a ticker→CIK index.

**H-3 · Filing history capped at `filings.recent`.** SEC's EDGAR APIs page: the `recent`
object holds *"at least one year's of filing or to 1,000 (whichever is more)"* and *"if the
entity has additional filings, `files` will contain an array of additional JSON files and
the date range"*. `files[]` is never read (verified by grep). For a heavy Form 4 filer,
`recent` may cover under a year, so `fetch_annual_reports(days_back=730)` silently returns a
truncated set. **This is the single biggest blocker to the long-history retrieval Codex
needs.**

**H-4 · Ownership/13F/144 parsers use three different conventions.** `Form4Processor` uses
namespace-free `findtext` with inline float coercion; `ThirteenFProcessor` uses
`_strip_namespace` + `_clean_text` + `_to_int` and a regex recovery fallback;
`Form144Processor` uses `_find_first`/`_child_text`/`_to_float` + date normalization. Three
independent copies of "read an XML element safely". `Form4Processor` was the weakest and had
no tests — which is exactly where C-5/C-6/C-7 lived. *Recommended:* one
`parsing/xmlutil.py` (namespace-tolerant element access, decimal/int/date/bool coercion,
footnote resolution) and have all three parsers use it.

**H-5 · `index.json` `type` field is an icon name, so every type-based branch was dead.**
Verified against live Form 4, 10-K and 13F-HR indexes: distinct `type` values are
`text.gif`, `compressed.gif`, `image2.gif`. Dead branches: `_find_primary_document_name`
(`'XML' in doc_type.upper()`, `'10-K' in doc_type`), `fetch_primary_html`
(`doc_type in ['10-K','10-Q',…]` → Tier 1 always empty),
`choose_information_table_document` (`"information" in doc_type` → +100 never awarded).
The 13F selector worked only by luck, via its `-20` penalty on `primary_doc.xml`; Berkshire
names its information table `50240.xml`, matching no name heuristic. *Fixed:*
`_document_type_is_meaningful()` guard, stronger XSL/cover-page exclusions, explicit `None`
(instead of a wrong pick) when only excluded candidates remain, plus a warning. Also fixed:
two `_find_primary_document_name` regexes used `\\d` inside raw strings (matching a literal
backslash, never a digit) — both dead; and `download_form_xml` could select
`xslF345X0N/…xml`, SEC's XSL-*rendered HTML* served under a `.xml` name, instead of the
machine-readable filing.

**H-6 · `anchor_type` is a public parameter that does nothing.** `sec_api.py:389` →
`form4_processor.get_insider_signal_payload(anchor_type=…)`, validated by `app.py` as
`^(filing_date|transaction_date)$`, but `_normalize_signal_event` hardcodes
`'event_anchor_type': 'filing_date'` and `anchor_timestamp = filing_date or
transaction_date`. `anchor_type` *is* part of the cache key, so requesting
`transaction_date` produces a second identical payload under a different key. Either
implement it or remove it.

**H-7 · Legacy financial path has no provenance or units.** `_get_fact_history` builds
entries carrying `filed`, `accn`, `unit`, `frame`, then strips all of them, emitting only
`{period, date, value, form}`. A consumer cannot tell which filing a number came from or
what currency it is in. For the newly added `ifrs-full` fallbacks this is a correctness
problem, not just a metadata gap: a foreign private issuer reporting revenue in TWD passes
the `preferred_units` filter (which only recognizes `USD`/`shares`) and is emitted as a bare
number. Note the tension to resolve with Codex: `financial_metrics.py` declares
`valid_units=("USD",)` while listing `ifrs-full` concepts, so IFRS filers currently yield
zero facts in the new path — inconsistent with the legacy path, which yields wrong ones.

**H-8 · Dependency footprint.** *(Fixed.)* `pyproject.toml` required `pandas`, `fastapi`,
`uvicorn[standard]`, `boto3`, `yfinance`, `duckdb` — ~131 MB of wheels — to parse a Form 4.
`duckdb` (45.9 MB) is used **only** by `analysis/phase0_thesis/`, which is not in the wheel
(`packages = ["src/copetech_sec"]`). `sec_api.py` imported `pandas` and never used it.
*Fixed:* core install is now `aiohttp` + `aiosqlite` (11 packages); everything else moved to
`dataframes` / `dotenv` / `service` / `analysis` / `dev` extras. Verified: a clean install
imports and parses a Form 4 with pandas and boto3 absent.

### MEDIUM

- **M-1 · `SECDataFetcher` is a god facade.** 614 lines spanning transport constants,

## 6. Public API assessment

### Current surface
One import (`from copetech_sec import SECDataFetcher`), one class, 22 async methods, flat
namespace. Return types: `Optional[Dict]`, `List[Dict]`, `Dict` — all `Any`-valued.

**Pain points**
1. **Datasets are indistinguishable by name.** `fetch_annual_reports`,
   `get_latest_13f_holdings`, `get_planned_insider_sales`, `get_8k_events`,
   `get_financial_series` sit in one flat namespace with no grouping.
2. **Raw vs normalized is not distinguished.** `get_company_facts` (raw SEC JSON) and
   `get_financial_summary` (heavily transformed) look alike.
3. **Return shapes are unpredictable** — bare list, `{symbol, window, as_of, events, …}`,
   `{manager_cik, filing, holdings, …}`, `None`.
4. **`None` is overloaded**: not found, throttled, network error, malformed response.
5. **Internals leak**: `app.py` reaches into `fetcher.form4_processor.detect_cluster_buys`
   (twice) because clustering has no facade method.
6. **Naming drift**: `symbol` vs `ticker`; `fetch_*` vs `get_*` with no rule.
7. **Silent no-ops**: `anchor_type` (H-6).

### Proposed stable API
Namespaced accessors over the existing processors — additive, no removals:

```python
from copetech_sec import EdgarClient

client = EdgarClient(user_agent="Your Name you@example.com")

issuer  = await client.issuers.resolve("NVDA")          # -> Issuer(cik, name, tickers, sic, ...)
filings = await client.filings.list(issuer, forms=["10-K", "10-Q"], since="2015-01-01")
txns    = await client.ownership.transactions(issuer, days_back=180)
signals = await client.ownership.signals(issuer, days_back=180)
clusters= await client.ownership.clusters(issuer, window_days=14)
revenue = await client.financials.series(issuer, metric="revenue", frequency="quarterly")
facts   = await client.raw.company_facts(issuer)         # raw SEC JSON, explicitly raw
doc     = await client.raw.filing_document(accession)    # raw bytes/str
```

Rules: every normalized return carries `provenance`; `raw.*` is the only place unmodelled
SEC JSON appears; not-found raises `IssuerNotFound`/`FilingNotFound`, never returns `None`;
absence of data is an empty collection plus a `warnings` list.

**Migration:** keep `SECDataFetcher` as a thin deprecated shim delegating to `EdgarClient`
(it is what CopeNet imports today). Add `client.ownership.clusters()` so `app.py` stops
reaching into `form4_processor`. One breaking change is unavoidable and already made: 13F
`value` scale (C-2).

## 7. Data-model assessment

Today: `Dict[str, Any]` everywhere, except `MetricDefinition` (frozen dataclass) and
`ServiceSettings` (frozen dataclass) — both good, both recent.

**Semantic weaknesses**
- `value` means: `shares × price` (Form 4 non-derivative), absent (Form 4 derivative,
  pre-fix), dollars ×1000 (13F, pre-fix), a fact's magnitude (financial). Four meanings, one
  key.
- `period` mixes fiscal (`"Q2 2025"` from `fp`+`fy`) and calendar (`"Q1 2025"` from `frame`)
  labels in one column (C-4).
- `cik` is variously a zero-padded `str`, an un-padded `str`, and an `int`
  (`company_facts['cik']`).
- `'N/A'` sentinel strings coexist with `None` for the same "missing" concept.
- Derivative and non-derivative rows had different key sets (fixed).

**Recommended rules** — a deliberate mixture, not one hierarchy:

| Boundary | Representation | Why |
|---|---|---|
| Raw SEC responses | `dict` unchanged | never reshape what SEC sent; keep it inspectable |
| Identifiers | tiny frozen value objects: `Cik`, `Accession`, `Ticker` | one normalization site; kills H-2/M-4. `Cik` stores the int, renders `.padded` / `.path` |
| Normalized domain rows | frozen `@dataclass(slots=True)` | `Issuer`, `Filing`, `FilingDocument`, `OwnershipTransaction`, `Holding`, `FinancialObservation`, `Provenance` |
| Public returns | dataclasses + `.to_dict()` / `.to_records()` | serializable without a Pydantic dependency |
| Internal intermediates | plain dicts | no ceremony where it buys nothing |
| Money / prices | `Decimal` at parse, `float` at the edge | Form 4 prices carry 4 decimals; 13F values reach 12 digits |
| Dates | `datetime.date` internally, ISO strings at the edge | lexicographic sorting already assumed everywhere |
| Optional fields | `None` only; never `'N/A'`, never `0.0` | C-7's root cause |
| SEC codes | `StrEnum` (`TransactionCode`, `AcquiredDisposed`, `FormType`) with `.label` | mislabeled `W` (C-5) would have been a one-line table |

Do **not** adopt Pydantic library-wide: it is a runtime dependency for data that is already
validated by SEC's own XSDs, and the goal is a *smaller* install (H-8). Dataclasses plus the
existing JSON-Schema-shaped agent layer are sufficient.

## 8. HTTP, rate-limit and caching assessment

**HTTP — after this audit:** one client, two pooled sessions (data / archive), one shared
request budget, `ClientTimeout(total, connect, sock_read)`, retries on 429/503 with bounded
exponential backoff plus safe `Retry-After`, non-retryable 400/403/404, 256 MiB response
cap, capability-detected `Accept-Encoding`, honest UA placeholder. Fully testable without
network (26 tests).

**Still open:** no `raise`-based error propagation (H-1); `Host` not derived from URL; no
"Undeclared Automated Tool" body detection; no per-host concurrency cap (the rate limiter
bounds throughput but 100 queued `gather` tasks still each hold a connection).

**Rate limiting — recommended target:** keep the reservation cursor; make it a small
injectable `RateLimiter` so a process-wide limiter can be shared by *multiple* client
instances (SEC's limit is per user, and `app.py` could grow a second fetcher).

**Caching — per-resource rules.** The current design conflates raw-response caching,
parsed-object caching, and normalized persistence. Recommended, modelled on how each SEC
resource actually changes:

| Resource | Key | Stored as | Mutability | Refresh | Invalidation |
|---|---|---|---|---|---|
| Ticker→CIK map | global | raw JSON | changes weekly | **TTL 7 d** (today: never) | replace atomically |
| Submissions `recent` | `cik` | raw JSON | daily | TTL 1 d | on date rollover |
| Submissions `files[]` pages | `cik/name` | raw JSON | **immutable once closed** | never for closed ranges | — |
| Company Facts | `cik` | raw JSON | on each filing | TTL 1 d | — |
| Filing index (`index.json`) | `accession` | raw JSON | **immutable** | never | — |
| Filing documents | `accession/doc` | raw bytes | **immutable** | never | — |
| Parsed ownership rows | `accession` + parser version | JSON | derived | version bump | version bump |
| Financial facts | `(cik, metric, concept, unit, start, end, accn)` | SQLite rows | **append-only** | new accessions only | never delete |
| Derived payloads | fingerprint(version, accessions, config) | JSON | derived | fingerprint mismatch | automatic |

The repo already implements rows 5, 6 and 9 correctly — the immutable raw store and the
payload fingerprint are the right primitives. Extend the same discipline to the rest rather
than building a generic cache abstraction whose semantics disappear.

## 9. Parser assessment

**Recommended pipeline** (the repo currently fuses stages 2–5 in each processor):
```
raw document → document detection → format parser → raw parsed model
            → normalized domain model → validation → public result
```
`Form4Processor` spans all of it *plus* analytics: 1,297 lines covering XML parsing, signal
classification, amendment dedupe, daily aggregation, cluster detection, LLM digest
construction, and payload caching. Extract three components:
`ownership/parser.py` (XML → rows), `ownership/normalize.py` (rows → events + amendments),
`insider/signals.py` (events → aggregates, clusters, digest). The parser is now
well-tested (32 tests), which makes that extraction safe.

**Resilience, after fixes:** namespace handling correct for EDGAR (not namespaced,
verified); missing elements → `None`; repeated elements handled (all owners, all rows);
footnotes resolved; nested ownership captured (`directOrIndirectOwnership` +
`natureOfOwnership`); derivative securities complete; malformed values → `None` not `0.0`;
decimal precision preserved; booleans accept `1/0/true/false/y/n`; direction from the
filing. Verified end-to-end against all six official SEC sample ownership documents and a
live Apple Form 4.

**Remaining parser gaps:** amendment linkage is heuristic (M-6, schema limitation);
`ET` hardening (M-11); no inline-XBRL parser; `supply_chain_parser` is regex-over-HTML and
should be labeled experimental.

**Extensibility:** a new form needs a parser class plus a `SECDataFetcher` method plus a
`FORM_TYPES` entry plus a cache `SUBDIRS` entry — four edits across three files. With
`resources/` + a parser registry it becomes one new module.

## 13. Agent integration design

Agent tools should be **adapters over the same public API humans use** — no agent
assumptions in the domain layer. CopeNet already consumes `get_financial_series` and
`list_supported_metrics` this way.

| Tool | Returns | Bounds |
|---|---|---|
| `edgar.resolve_issuer` | `{cik, name, tickers[], sic, fiscal_year_end}` | — |
| `edgar.list_filings` | `{filings[], next_cursor, truncated}` | `limit` ≤ 100, cursor paging |
| `edgar.get_filing` | `{metadata, documents[], document_handles[]}` | **never** document bodies |
| `edgar.get_filing_document` | `{content, truncated, byte_length}` | explicit `max_bytes` |
| `edgar.get_insider_transactions` | `{transactions[], provenance[], warnings[]}` | window + limit |
| `edgar.get_company_facts` | `{concepts[], available_units[]}` | **index, not the 4 MB blob** |
| `edgar.get_financial_series` | existing `financial_series` payload | already correct |
| `edgar.inspect_fact_provenance` | `{accession, form, filed, concept, taxonomy, source_url}` | — |
| `edgar.list_supported_metrics` | registry | already exists |
| `edgar.audit_issuer` | `{coverage{}, gaps[], warnings[]}` | — |

Contract for every tool: structured and JSON-serializable; **no unbounded documents by
default** (return handles); provenance on every value; **missing data ≠ tool failure**
(`{data: [], warnings: ["no_filings_in_window"]}` vs. raising `ThrottledError`); expose
`confidence` and `quality_flags` (already present in `financial_series`); cursor pagination;
raw handles for deeper inspection.

This is blocked on H-1: without an error model an agent cannot tell "no data" from "SEC
throttled us", which is exactly the distinction that makes an agent trustworthy.

  `thirteenf_processor`.

## 16. Marketing and positioning

### What problem does it actually solve?
SEC publishes the data; it does not publish *usable time series*. Getting quarterly revenue
out of Company Facts means knowing that `fy`/`fp` describe the filing rather than the fact,
that a 10-Q carries both a quarter and a year-to-date figure, that companies migrate
concepts mid-history, and that the same fact reappears in later filings with a different
fiscal label. Getting insider *direction* right means knowing that both legs of an option
exercise share one transaction code and that only `transactionAcquiredDisposedCode`
distinguishes them. **This audit found five production defects of exactly that kind — the
strongest possible evidence that the domain knowledge is the product.**

### Who is it for?
Python developers and agentic systems building market-analysis tooling who need SEC data
they can audit back to a filing — not a paid API with opaque normalization, and not a
scraper.

### What it provides over raw SEC endpoints
1. **Point-in-time correctness with provenance.** Every observation carries the accession,
   form, filing date and source URL, and `as_of` returns what was *knowable* on a date —
   what backtesting requires and what most wrappers get wrong.
2. **Download-once immutability.** Filings are content-addressed by accession and never
   re-fetched; parser fixes re-derive from local data at zero SEC traffic. This is fair
   access by construction, not by politeness.
3. **Corrections encoded as tests.** The 13F whole-dollar change, both legs of an option
   exercise, joint-filing co-owners, holdings-only Form 3 — each is a regression test.

### Three credible differentiators
- *Auditable*: every number links back to the filing that reported it.
- *Point-in-time*: `as_of` queries, `availableAt` per observation, amendment-aware.
- *Polite by design*: a shared 10 req/s budget and an immutable filing store.

### One-sentence description
> **CopeTech-Edgar turns SEC EDGAR filings into auditable, point-in-time Python data — every
> value traceable to the filing that reported it.**

### README opening
> SEC EDGAR gives you filings. CopeTech-Edgar gives you data you can defend.
>
> It resolves issuers, walks filing history, parses ownership and institutional-holdings
> XML, and normalizes XBRL Company Facts into time series that keep their provenance — the
> accession number, form type, filing date, and source URL behind every number. Queries are
> point-in-time by default, so you see what was knowable on a given date rather than what
> was restated later. Filings are downloaded once, stored immutably, and re-parsed locally,
> so it stays inside SEC's 10 requests/second fair-access guidance without you thinking
> about it.

### The compelling example
```python
series = await client.financials.series("NVDA", metric="revenue", frequency="quarterly")
for obs in series["observations"][-4:]:
    src = obs["sources"][0]
    print(f"{obs['periodEnd']}  ${obs['value']:>15,.0f}  "
          f"known {obs['availableAt']}  {src['form']} {src['accessionNumber']}")
```
It shows the differentiator in six lines: a clean series, *and* the filing behind every
point, *and* when each became knowable.

### Honest status statement
> **Status: pre-1.0, actively developed.** Ownership-form parsing (Forms 3/4/5),
> filing discovery, raw document access and 13F-HR parsing are verified against SEC's
> official XML technical specifications and covered by regression tests. The financial-series
> normalizer is beta and under active development. Filing history is currently limited to
> what SEC's submissions `recent` block contains (roughly one year or 1,000 filings);
> paging into older filings is in progress. Insider "signal" scoring and supply-chain
> extraction are experimental heuristics, not investment advice.

### Positioning: staged
Not "a general SEC API client" — that market has `sec-edgar-downloader`, `edgartools`,
`python-edgar`. Stage it:
1. **Now:** *the auditable insider- and institutional-ownership library* — the deepest,
   best-tested capability, and the one where competitors are demonstrably wrong (both
   option-exercise legs as buys; 13F values ×1000).
2. **Next:** *point-in-time XBRL financials with provenance* — once Codex's series work and
   `files[]` paging land.
3. **Then:** *the agent-ready SEC research layer* — once the error model exists, because
   "missing data vs. tool failure" is the whole game for agents.

Do not lead with "access SEC data." Lead with **"both legs of an option exercise are not two
purchases"** — a concrete, checkable claim that demonstrates the domain knowledge buyers
cannot get from the raw endpoints.

## 17. Coordination with Codex

**Files this audit did not touch:** `financial_series.py`, `financial_series_service.py`,
`financial_series_store.py`, `financial_metrics.py`, `financial_processor.py`,
`tests/test_financial_series.py`.

**Overlapping concerns to settle jointly**

1. **C-4 belongs to Codex.** The duplicate/mislabeled-period defect lives in
   `financial_processor.py`, which is the legacy version of exactly the path Codex is
   rebuilding. Recommendation: do not repair it — retire it and route
   `get_financial_summary` / `get_financial_trend` through the `financial_series` resolver,
   which already keys on `(period_start, period_end, unit)` and separates fiscal identity
   from calendar frames.
2. **The metric registry should be the single source of truth.** The revenue concept chain
   existed in three places; this audit deleted the dead `tag_mapping.py`, leaving two:
   `financial_metrics.METRIC_REGISTRY` and
   `financial_processor.KEY_FINANCIAL_SUMMARY_METRICS`. `financial_metrics` should win, and
   `financial_processor` should import from it.
3. **Units are inconsistent between the two paths.** `financial_metrics` declares
   `valid_units=("USD",)` while listing `ifrs-full` concepts — so IFRS filers yield zero
   facts in the new path, while the legacy path emits their native-currency values as bare
   unlabelled numbers (H-7). Neither is right. Decide: reject non-USD explicitly, or carry
   the unit through and label it. Note EPS needs `USD/shares`, so `valid_units` must be
   per-metric regardless.
4. **`filings.files[]` paging (H-3) is the shared unblocker.** Long-history retrieval needs
   it. It belongs in a `resources/submissions.py` owned by the foundations work, not in the
   financial path.
5. **Shared abstractions Codex should adopt as they appear:** `exceptions.py` (so
   `get_series` can distinguish "no facts" from "fetch failed" — today it returns `None` for
   both and separately emits `source_refresh_failed_using_persisted_facts`),
   `identifiers.Cik` (`_source_from_fact` does its own `lstrip("0")`), and the
   `Provenance` dataclass (the `sources[]` shape is already the right contract — it should
   become the library-wide one).
6. **No conflicting assumptions found.** The `financial_series` design and this audit's
   direction agree: provenance everywhere, immutability, point-in-time, quality flags.
